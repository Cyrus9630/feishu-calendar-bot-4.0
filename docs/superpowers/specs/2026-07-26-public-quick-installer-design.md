# 飞书日程机器人 4.0 公开版快速安装器设计

## 一、目标与适用范围

本次改造只适用于 `feishu-calendar-bot-4.0` 公开仓库，不修改自用版本。安装者完成飞书 CLI 安装后，应当能够通过 Windows 或 macOS 双击入口启动向导；向导负责检查、发现、选择、部署和验证，避免要求安装者查找或手工填写群聊 ID、用户 open_id、日历 ID及妙搭应用 ID。

飞书 CLI 是安装者需要主动准备的唯一软件前置条件。飞书 CLI 未安装时，入口应当先显示明确提示、官方安装命令和官方项目地址，然后停止，不得继续显示无关的 Node.js、Git 或项目构建错误。飞书 CLI 已安装但尚未完成应用配置或用户授权时，向导调用飞书 CLI 的官方配置、登录流程，并由浏览器承接用户本人必须完成的登录和授权。

## 二、平台边界

根据飞书 CLI 当前公开命令，向导可以读取当前登录用户、列出该用户可见的群聊和具有编辑权限的日历，也可以创建妙搭全栈应用、初始化项目、设置线上环境变量、推送源码并等待发布完成。向导应当使用这些能力自动生成或发现参数，不要求安装者复制技术标识。

飞书 CLI 的 `config show` 会遮盖 App Secret，当前没有公开命令可将其已保存的密钥直接转交妙搭。因此，向导不得读取钥匙串或依赖飞书 CLI 的内部存储格式。安装者仍需在自动打开的飞书应用页面中复制 App Secret 和 Verification Token，并通过隐藏输入交给向导；Encrypt Key 仅在安装者启用事件加密时填写。飞书应用权限、事件订阅、应用版本发布和机器人入群仍需账号本人在飞书页面确认，向导负责打开准确入口、提供当前部署对应的回调地址并压缩为最少点击。

## 三、安装流程

### 1. 双击入口

Windows 和 macOS 入口首先检查 `lark-cli`。未找到时，显示：

- 飞书 CLI 尚未安装；
- 官方一键安装命令 `npx @larksuite/cli@latest install`；
- 官方项目地址；
- 安装完成后重新双击当前文件。

找到飞书 CLI 后再检查向导运行所需的 Node.js 和 Git。由于官方 npm 安装方式会同时依赖 Node.js，正常安装者通常无需额外处理；检测到异常环境时，应当提示重新运行飞书 CLI 官方安装流程或按当前系统安装 Git，不得进入半完成部署。

### 2. 配置与授权

向导依次运行只读状态检查：

- `lark-cli doctor`；
- `lark-cli config show`；
- `lark-cli auth status --json --verify`；
- `lark-cli whoami`。

尚未配置应用时，调用 `lark-cli config init --new`；尚未完成用户授权时，调用限定业务域的登录流程，至少包含 `apps`、`im` 和 `calendar`。浏览器中的登录、授权和组织确认由安装者本人完成。成功后重新读取状态，不根据命令启动成功推定授权已经完成。

### 3. 自动发现安装对象

向导从 `whoami` 读取当前用户 open_id，不再询问 `TARGET_OPEN_ID`。向导通过 `im +chat-list` 列出最近活跃的群聊，以编号、群名和外部群标识供用户选择；不得默认选择第一个群。向导通过 `calendar calendars list` 列出 `owner` 或 `writer` 权限、未删除且非第三方只读的日历，以编号、日历名、类型和权限供用户选择；不得显示只有读取权限的日历作为可部署目标。

如果权限不足，向导应当提取飞书 CLI 错误中的 `hint` 或 `console_url`，打开或展示原始地址，并在用户完成授权后允许重试。错误信息不得包含令牌、密钥或完整环境变量值。

### 4. 飞书应用信息

向导复用飞书 CLI 当前配置中的飞书应用 ID，并自动打开该应用的开发者后台。用户只需完成以下事项：

1. 确认机器人能力已经启用；
2. 复制 App Secret 和 Verification Token，按向导提示隐藏输入；
3. 仅在启用事件加密时输入 Encrypt Key。

向导通过飞书接口验证 App ID 与 App Secret，并取得机器人 open_id。验证失败时仅说明凭据不匹配或权限缺失，不回显秘密。

### 5. 自动部署

向导汇总应用名称、目标群名称、目标用户和目标日历名称，要求用户输入一次“开始部署”。该确认同时授权创建新的妙搭应用、写入该应用的线上环境变量、提交并推送脱敏源码以及发起妙搭发布。

确认后，向导自动执行：

1. 创建新的妙搭全栈应用；
2. 初始化新的本地妙搭项目；
3. 复制 4.0 公开版脱敏源码；
4. 通过标准输入设置线上环境变量；
5. 提交并推送 `sprint/default`；
6. 发起发布并轮询同一 `release_id`，直至 `finished` 或明确失败。

只有 `release-get` 返回 `finished` 且包含 `online_url`，才能进入后续飞书设置。

### 6. 最少人工收尾

发布完成后，向导生成回调地址，自动打开飞书应用后台，并逐项显示：

- 需要启用的机器人、消息、卡片和日历权限；
- 事件回调地址；
- `im.message.receive_v1` 与 `card.action.trigger`；
- 应用版本发布入口；
- 将机器人加入所选群聊；
- 将所选日历以编辑权限共享给机器人。

向导不声称这些页面操作已经自动完成。安装者完成后返回向导，选择“开始验收”；向导执行健康检查，并提示用户在所选群发送一条测试日程。只有线上健康检查、消息接收、确认卡片和目标日历写入均实际通过，才显示安装完成。

## 四、组件边界

- 跨平台入口只负责前置检查、打开安装说明并启动 Node.js 向导。
- `cli.mjs` 只负责编排状态、交互和阶段推进。
- 新增的飞书发现模块负责解析 `config show`、`whoami`、群聊列表和日历列表，不保存秘密。
- 现有妙搭部署模块继续负责创建、初始化、复制、环境变量、Git 推送和发布轮询。
- 核心校验模块负责选择编号、必要字段和安全退出，不包含平台调用。
- README 和欢迎页以快速安装为默认入口，详细手册保留为故障排查材料。

## 五、错误处理与恢复

每一步失败都停留在当前阶段，不删除已创建的妙搭应用或本地目录。重复运行时应当生成新的独立项目目录，不覆盖已有项目。授权不足、网络中断和发布仍在进行时，向导应当给出可执行的恢复方式；不得用示例 ID 或猜测值继续部署。

秘密只存在于当前进程内存和妙搭秘密环境变量写入的标准输入中，不写入源码、报告、命令参数或普通日志。部署结果文件只记录应用 ID、本地目录、线上地址、回调地址和不含密钥的收尾清单。

## 六、验证标准

实现应当通过以下验证：

1. 飞书 CLI 缺失时，Windows 和 macOS 入口均先给出安装提示并停止；
2. CLI 已配置和未配置、已登录和未登录状态均有自动化测试；
3. `whoami`、群聊列表和日历列表的不同 JSON 信封能够稳定解析；
4. 群聊和日历只能通过明确编号选择，非法编号不得推进；
5. App Secret、Verification Token 和 Encrypt Key 不出现在命令参数、报告或测试日志；
6. 妙搭创建、环境变量写入、Git 推送和发布轮询的既有测试继续通过；
7. 公开版已明确排除的旧功能及相关依赖扫描保持零结果；
8. TypeScript 类型检查、机器人测试、生产构建和全新 GitHub 发行包解压验收全部通过。
