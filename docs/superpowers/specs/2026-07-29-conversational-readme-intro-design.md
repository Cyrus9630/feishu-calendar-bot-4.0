# GitHub 首页口语化介绍设计

## 目标

将 README 首页最前面的介绍改为更口语、更容易理解的表达，使第一次打开仓库的人立即知道：机器人使用时不需要记命令，安装时不需要手工查找技术 ID。

## 接收者与使用场景

主要接收者是想在自己的飞书中部署日程机器人的普通用户。文案显示在 GitHub 仓库首页，应当先回答“好不好用、好不好装”，再进入功能清单和完整部署说明。

## 文案结构

1. 保留标题“飞书日程机器人 4.0”及英文介绍入口。
2. 将首句改为“能聊天就会用，会双击就能装。”
3. 用一个完整段落说明使用方式：在群里 @机器人后直接说人话，不需要记固定命令。
4. 用一个完整段落说明安装方式：双击安装程序、登录飞书、按编号选择群聊和日历，不需要手工查找群聊 ID、用户 open_id、日历 ID 或妙搭应用 ID。
5. 保留四条真实指令示例，随后再介绍项目性质和安全边界。

## 事实边界

“会双击就能装”是对安装路径的口语概括，不表示飞书平台的强制确认可以被绕过。正文必须紧接着说明：飞书要求账号本人完成的登录授权、应用权限、版本发布、机器人入群和日历共享仍需手工确认。不得使用“一键完成全部安装”“完全不需要配置”等与现有安装流程不符的绝对表达。

## 验收标准

- 首页首屏出现“能聊天就会用，会双击就能装”。
- 首屏明确说明“不需要记固定命令”和“不需要手工查找技术 ID”。
- 首屏准确列出仍需账号本人确认的飞书平台操作。
- 原有功能示例、公开源码边界和后续完整部署说明保持不变。
- Markdown 结构正常，法律文风检查脚本无高风险表达提示。
